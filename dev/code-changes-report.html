Eight substantive defects: four in the score that assigns locations to clusters, three in the numerical engine inherited from version 1.0, one introduced and corrected during this work. Defects in the cluster assignment score

SCSTEM_Estimation, before 2.0.0

The score deciding which cluster a location belongs to contained four defects. None produced an error: they silently produced the wrong partition, and therefore the wrong cluster-wise coefficients.

What was thereConsequenceSeverity
The quadratic form of the state equation was divided by m0 instead of Sigmaeta — indices ncov+4 against ncov+3 of the flattened parameter vector. m0 is a mean, not a variance, and is routinely negative on log-transformed data. When it is, the term changes sign and the score rewards the worse fit. Critical
sigma2omega and sigma2eps were read from the pooled fit rather than from the candidate cluster. The term becomes constant across clusters and drops out of the argmax. The nugget_var argument therefore had no effect at all, with either value. Critical
The predictor used the lagged smoothed state y[t-1]. The measurement equation is z_t = X_t beta + K y_t + e_t: the fit was being evaluated against the wrong state. Major
The score was divided by the number of locations. An arbitrary rescaling between the likelihood and the penalty, leaving phi_penalty without an interpretable scale and not comparable across datasets. Major

The contribution is now an explicit conditional pseudo-likelihood, documented as such, and used only to rank clusters: every reported quantity comes from the exact cluster-wise likelihoods of the final refit.

Robustness of the numerical engine

Pre-existing, inherited from version 1.0

Three defects in code that predates this work. They were harmless for a single pooled fit, which is how the package had always been used, and fatal for a clusterwise algorithm, which refits the model on hundreds of different subsets of locations.

WhereWhat was thereConsequenceSeverity
kalman The Newton-Raphson step was used without validation: a singular or non-finite Hessian, a zero denominator in the relative criterion, and a fallback grid search that could evaluate log(0) when the scale underflowed. NaN reaching the while condition, hence “missing value where TRUE/FALSE needed” and an aborted fit. Critical
STEM_Estimation The same pattern in the outer EM loop, with no check on the iterate itself. The same error. Measured effect: the parametric bootstrap went from 4 usable draws out of 12 to 12 out of 12 once both were fixed. Critical
filterstep The univariate branch computed the predictive mean as f - X beta. Equation (9) gives mu_t = X_t beta + K y_t: the regression term is added, as the multivariate branch three lines above does correctly. Reached only when a fit has a single location — essentially never for a pooled model over a network, but reachable cluster by cluster. Produced a silently wrong log-likelihood, hence wrong information criteria and a wrong assignment. Major

All three now keep the last valid iterate and warn, rather than propagating a non-finite value into a logical test. Found while reading the reference papers against the code.

Consequence for earlier results

Clustered results produced with the previous version are not comparable with the current ones. This includes those in script/sugasawa amkm 3 cluster bootstrap param 10 perc.R in the Google Drive folder, which predates the rewrite.

Defect introduced during this work

And how it was caught

WhereWhat happenedFix
SCSTEM_Bootstrap The arguments of the refits were rebuilt from a settings list stored in the fitted object. When an argument was later removed from SCSTEM_Estimation, every draw failed with “unused argument” — reported only as a lost replicate, so the bootstrap silently returned nothing usable. The forwarded list is now filtered against formals(SCSTEM_Estimation), and a regression test asserts the invariant.
STEM_Simulation mvrnorm() was called unqualified, working only through a NAMESPACE import; it broke as soon as the file was sourced directly. Now MASS::mvrnorm(). Every external call in the package is namespaced.

Algorithmic changes in SC-STEM

Adapting the apparatus of the spatially-clustered literature

Before

  • Simultaneous label update, without guarantees and able to cycle
  • Information criteria counting the number of clusters as the number of parameters
  • No selection of the penalty; k chosen by minimizing BIC with no safeguards
  • Bootstrap conditional on the partition
  • AMKM initialization from SCDA, a package not on CRAN
  • Asymmetric k-nearest-neighbor graph used for an undirected penalty

After

  • Sequential ICM sweep, penalty recomputed on the fly; the simultaneous update kept as an option
  • k_eff * (ncov + 3 + 3p) parameters, n = d*T observations, exact log-likelihood of the final refit
  • Two-step rule: BIC inside a moderate band, then the smallest penalty on the ARI stability plateau
  • Refit-with-clustering bootstrap: the partition is re-estimated at every draw
  • Internal k-means on PCA-compressed covariate means, with an admissibility filter and a repair step
  • Graph symmetrized

Two mechanisms that had to be added

The first was found empirically: without constraints the partition always collapses. The cluster with the smallest residual variance attracts every location — the clusterwise counterpart of the degenerate-likelihood problem of Gaussian mixtures. On the pm10 data it collapses to a single cluster even with the penalty set to zero.

The remedy is a minimum-size constraint in the sweep. But the constraint freezes the locations of any cluster sitting at the threshold, and with small networks most of the partition then stays at its initial value. Hence the second mechanism, a size-preserving swap pass: it exchanges the labels of two locations when doing so increases the objective. Cluster sizes are unchanged, so feasibility holds by construction, and a swap is accepted only on strict improvement. An exact bound on the achievable penalty gain discards most candidate pairs without evaluating them.

A property worth knowing

A test written against the cross-sectional intuition failed, and it was right to: the alternation is not globally monotone. In the STEM measurement equation the spatial covariance couples the locations, so the exact marginal likelihood does not factorize and the assignment score must be a pseudo-likelihood, while the parameter step maximizes the exact within-cluster likelihood. A parameter update can therefore lower the penalized objective while raising the exact likelihood.

This is a property of the spatio-temporal specification. The implementation copes by always returning the best partition visited, reporting both best_objective and last_objective; it is documented in ?SCSTEM_Estimation and in the SC-STEM vignette.

The scale of the penalty

Transferring the penalty from the cross-sectional literature does not work: there each unit contributes one observation, here it contributes T, and the log-likelihood differences between clusters grow with T and with the scale of the response. The default phi_scale = "auto" normalizes by the median spread of the per-location contributions divided by the average number of neighbors, so that phi around one is the point where agreeing with the neighborhood is worth about as much as picking the best-fitting cluster, and a grid on [0, 2] is informative on any dataset. "per-observation" and "raw" remain available.

Issues the check raised on its own

  • pm10 was source code, not data: the same 250 KB file was duplicated in R/ and data/. It is now data/pm10.rda, 25 KB.
  • SCDA is not on CRAN: an unreachable dependency in Imports is an automatic rejection. Removed; the initialization is internal and any external partition can be supplied through the new init_partition argument.
  • dplyr and sf were unused: removed. Every external call is written package::function() and NAMESPACE carries no importFrom.
  • ts() unqualified in filtering() and smoothing() (NOTE); verbose undocumented in two manual pages (WARNING); the STEM_Bootstrap example running over five seconds (NOTE).
Two operational traps, documented in cran-comments.md

Do not run the check inside OneDrive. R CMD check creates thousands of small files and the sync client stalls it: it hangs at checking package dependencies indefinitely. Outside OneDrive it completes in minutes.

Pandoc is needed for the vignettes and for checking README and NEWS. If it is not on the path: Sys.setenv(RSTUDIO_PANDOC = "C:/Program Files/RStudio/resources/app/bin/quarto/bin/tools").

Verification

What is checked, and how

The testthat suite covers the invariants that the defects above violated:

  • the pooled SC-STEM fit at k = 1 reproduces STEM_Estimation exactly;
  • the returned partition is admissible and attains the best visited objective;
  • the parameter count behind the information criteria is k_eff * (ncov + 3 + 3p) and the sample size is d * T;
  • the neighbor graph is symmetric with a zero diagonal;
  • the ICM sweep is monotone at fixed parameters, and the swap pass preserves cluster sizes;
  • estimation leaves the caller's RNG state untouched;
  • the bootstrap is reproducible under a fixed seed, produces usable draws, and forwards only arguments that SCSTEM_Estimation accepts.

43 assertions, all passing. R CMD check --as-cran reports Status: OK with no errors, warnings or notes.
